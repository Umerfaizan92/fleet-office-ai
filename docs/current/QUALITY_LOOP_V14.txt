V14 MAKER / CHECKER QUALITY LOOP

Principle: the component that creates output should not be the only component that decides it is good.

Product quality path:
1. Maker creates a draft/output.
2. Separate checker/verifier evaluates explicit criteria.
3. Verdict is pass/fail with score and lesson.
4. Every run is logged in ai_verification_runs / qa/results.tsv.
5. A quality ratchet fails the software audit if the independent static score drops below the recorded floor.
6. Consequential actions still require authorised human review; an AI checker is not a substitute for legal/professional approval.

Commands:
npm run quality:check
npm run validate:final
